    4 Estimate

    How the estimate works

    Code refactoring from BPA

    Findings are de-duplicated and grouped into about 20 refactoring buckets, such as static templates to editable templates, Classic UI dialogs, Oak indexes, replication agents and asset workflows. Each bucket has a per-item rate up to a threshold and a bulk rate beyond it.

    Platform and content

    Cloud Manager, repository restructuring and Dispatcher conversion scale with the number of sites. Content migration scales with repository size, asset count and the number of Content Transfer Tool rehearsals.

    QA from the live site

    Test design and execution scale with templates, components, locales, forms and integrations, multiplied by test cycles. Migration validation samples pages, and non-functional testing is added when selected.

    Getting a good estimate

    • Run BPA on a recent copy of production, not a stale development instance, so content counts and findings are real.
    • Add the integrations you can't see. Back-end connections such as search, PIM, CRM, SSO and translation never show up in page HTML, and each needs re-pointing and testing.
    • Calibrate the rates once. After your first migration, compare actuals with this model and save your own rates. That's what turns an estimate into a forecast.
    • Read the method: my posts on estimating AEM projects and the AEMaaCS migration playbook explain the reasoning behind these numbers.
