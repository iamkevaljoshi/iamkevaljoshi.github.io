Advanced options
Pages that can't be fetched (staging, logins, VPN)

Paste the page HTML and upload a full-page screenshot. Anything you provide here replaces fetching for that side.

URLs are sent to Jina Reader to render and screenshot them. Nothing is stored on this site. Use public pages only, or paste HTML for private ones.

    What it checks

    UI parity

    Full-page screenshots of both pages at the same viewport, compared pixel by pixel. You get a difference map, a first-screen score, changed regions, colour palette similarity and a count of structural elements such as headings, forms, buttons and landmarks.

    Content parity

    The rendered text, compared block by block with word-level highlighting, plus the heading outline, internal and external links, and images matched by file name or alt text.

    SEO and metadata

    Title, meta description, H1, canonical, robots, language, hreflang, Open Graph and structured data. It flags the classic migration mistakes, such as a noindex left on, or a canonical still pointing at the old domain.

    Tips for migration QA

    • Set content scope to the main content area of each platform, such as .root on AEM 6.5 and main on Edge Delivery Services, so header and footer differences don't drown out page differences.
    • Add your AEM content root, such as /content/mysite, as a path prefix so /content/mysite/en/about.html and /en/about count as the same link.
    • Remove cookie banners, chat widgets and rotating carousels with ignore elements. They change between two captures of even the same page, and add noise to the score.
    • Compare at mobile as well as desktop. Responsive regressions are the most common UI gap after a re-platform.
    • Use Download JSON to keep evidence for each page you sign off.
